# TypeScript 与本地中文内容后台方案

日期：2026-10-17。网站：Canberra Woodwork。

## 用户目标与边界

用户在自己的电脑上修改中文网站内容，保存后由 Codex 同步对应英文、检查双语页面、制作完整上传包，再按用户发布指令上传。后台本地运行，不需要 GitHub 登录、邮箱密码、在线管理账户或云数据库。

以当前正式提交 `e5650ab8a33e44b10a46e693434a33ebe230bafe` 为迁移基准。代码语言迁移和后台建设不得顺带改写已有正文、标题、业务资料或重排页面，不重新采用此前撤回的 SEO/UI 修改。网站既有图片、样式、路径、锚点、双语关联、内链和联系邮件行为继续保留。

## 推荐结构

1. 全站生产逻辑使用 TypeScript：页面构建、内容处理、双语生成、浏览器交互及联系 API。HTML、CSS、图片及可编辑内容仍采用适合它们的文件格式。使用真实类型检查，不通过全局关闭检查完成迁移。
2. 本地后台由 Node.js/TypeScript 启动，绑定 `127.0.0.1`。一个本地地址提供内容管理及中英文预览；提供 Windows 启动入口，关闭后台不会丢失已保存内容。所需运行环境和依赖纳入交付说明。
3. 中文、英文以稳定的页面及内容字段 ID 关联，避免以正文哈希作为唯一编辑 ID。保留原始内容作为迁移参考，将可编辑内容与页面模板分离；无编辑时，输出与当前正式站对应。
4. 本地草稿、历史记录与待同步清单存放在本站目录内，正式内容存入可版本管理的数据文件。后台不需要直接提交 Git 或联网发布。

## 后台操作

按首页、关于、服务、FAQ、文章、案例、地区和联系/隐私页面组织页面列表。支持按中文标题或关键词搜索。

编辑区展示所属页面和内容位置。可编辑标题、导语、段落、FAQ 问答、图片及图片说明、链接和 SEO 标题/描述。正文保留段落及内链关系，不暴露原始 JavaScript/TypeScript 代码。全站共用文字独立列出，修改时明确提示影响多个页面。原有栏目顺序、布局和 CSS 不作为普通内容编辑功能开放。

提供保存草稿、查看修改前后、恢复某次保存、中文预览和查看英文同步状态。图片通过文件选择器复制到受管理的媒体目录，保留原图，避免覆盖其他项目照片。新增页面、改变页面路径或重新设计栏目不纳入第一版。

所有操作写入真实本地文件，不只保存在浏览器缓存。文件写入采用校验、备份和原子替换；旧版本保存导致冲突时提示重新加载，不静默覆盖其他修改。

## 中文修改与英文同步

中文保存后，该字段标记为“英文待同步”。清单记录稳定 ID、页面、原中文、新中文、当前英文、版本及来源，不改变线上内容。

用户修改完成后通知 Codex。Codex 读取本地变更清单，只同步相关英文，并检查相应标题、描述、图片说明、内链、文章 feed 和结构化数据。英文记录关联中文修订版本，中文再次变化后重新标记待同步。免费模型只处理获准的简单翻译子任务，输出由 Codex 核查；本地后台不要求用户配置翻译 API，也不承诺在聊天未运行时由 Codex 自动监控。

有待同步、字段不合法、链接失效或检查失败时，阻止制作正式发布包。中英文预览可以显示草稿及其状态，但不得把旧英文标为已同步。

## 上传包与发布

发布包保存在本站 `reports` 下按日期和版本划分的交付目录。包含完整 TypeScript 发布源码、已确认双语内容、媒体、依赖锁文件、Vercel 配置、构建后的静态网站、文件清单/校验值及操作说明；排除密钥、`.env`、Git 内部目录、依赖目录、未确认草稿和本地历史备份。

另外可提供静态成品 ZIP 作为备份，但它不能独立替代联系邮件 API 的服务端运行能力。正式上传继续沿用此站 GitHub → Vercel 自动构建，保证联系表单保留。仅在用户当次授权后推送正式分支，核对实际构建提交、状态、正式域名及中英文页面。

## 本地访问与数据约束

后台只监听本机。写操作校验 Host、Origin 和本地会话防伪标记，不接受任意文件路径或任意命令执行。管理服务及草稿不会放到公开网站的 `/api` 路由中。预览不发送真实询价。电话、邮箱和公司身份集中管理并显示明确的全站影响提示。

## 验收标准

- 无内容编辑时，中英文正文、标题、图片、链接、SEO 事实与现正式站一致；原页面布局及交互行为保持一致。
- TypeScript 类型检查、构建和联系 API 的模拟测试通过，现有功能检查按迁移后的结构继续执行。
- 中文编辑在重启后台后仍存在；能查看修改记录并恢复；保存不会直接发布。
- 代表性标题、段落、FAQ、图片说明和链接修改能出现在中文预览中；对应英文正确标记待同步。
- 英文同步只影响对应字段；元数据、文章 feed 和页面可见文本一致；遗漏英文或保存冲突会阻止发布包生成。
- 桌面和手机检查无新增溢出、导航或语言切换故障。用无真实邮件发送的方式核对表单行为。
- 上传包能在独立临时目录按说明安装依赖并重建同一内容；正式产物不含本地后台草稿、私密文件或密钥。

## 实施与当前状态

先完成内容模型及 TypeScript 迁移的输出对比，再建设本地编辑、保存、版本记录和预览，最后连接人工英文同步清单及打包检查。第一版交付本地后台和可验证上传包流程，用户编辑完成后再进行相应内容同步及发布。

当前仅完成源码核对和本设计文件；未安装产品依赖、未迁移代码、未创建后台，线上版本未变化。此文件按方案设计工作流供用户审核，通过后编写实施计划。
